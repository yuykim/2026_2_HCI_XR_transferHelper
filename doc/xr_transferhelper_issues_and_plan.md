# XR TransferHelper 현재 문제점 및 향후 계획

## 1. 현재 진행 상황
- Meta Quest 3에서 passthrough 실행 확인
- 데모 오브젝트 표시 및 버튼 기반 정렬 기능 확인
- `Align` 버튼 클릭 시 `NavigationRoot`가 `AlignTarget` 기준으로 재배치되는 동작 확인
- 테스트용 경로 오브젝트(`Cube`, `Capsule`) 배치 완료

## 2. 현재 문제점

### 2-1. 정렬 방식의 한계
현재 구현은 **버튼을 눌렀을 때 한 번 정렬되는 구조**이다.  
즉, `NavigationRoot`가 `AlignTarget` 위치와 회전에 맞춰 재배치될 뿐,  
사용자가 실제 공간에서 이동하는 동안 지속적으로 보정되지는 않는다.

### 2-2. 길 안내가 아니라 "배치 데모"에 가까움
현재는 길처럼 쭉 이어진 경로를 따라 걷는 내비게이션이라기보다,  
정렬 버튼을 눌렀을 때 가상 오브젝트가 특정 위치에 놓이는 데모에 가깝다.

### 2-3. 사용자가 걷기 시작하면 경로가 다시 멀어짐
처음 정렬 직후에는 경로가 맞는 것처럼 보여도,  
조금 이동하면 가상 경로가 다시 멀어지거나 어긋나는 현상이 발생한다.

### 2-4. 실제 기준점이 아닌 임시 기준점 사용
현재는 `AlignTarget`이라는 **씬 내부의 가상 기준점**을 사용하고 있다.  
이 방식은 정렬 로직을 확인하는 데는 유용하지만,  
현실 공간의 고정 기준점으로 쓰기에는 한계가 있다.

### 2-5. 긴 경로에 대한 보정 구조 부재
하나의 기준점만으로 전체 경로를 고정하려고 하면  
경로가 길어질수록 오차가 더 크게 느껴질 수 있다.  
특히 실제 이동이 포함되면 중간 보정 없이 안정적인 안내가 어렵다.

### 2-6. 방향 정렬의 중요성
위치뿐 아니라 **회전값(Y축 방향)** 이 매우 중요하다.  
초기 방향이 조금만 틀어져도 경로가 옆으로 밀리거나  
사용자가 느끼기에 경로가 점점 어긋나는 것처럼 보일 수 있다.

## 3. 현재 문제의 원인 요약
- 정렬이 **1회성 버튼 동작**에 머물러 있음
- 경로가 **현실 기준점에 지속적으로 고정되지 않음**
- `AlignTarget`이 실제 QR/마커가 아닌 **테스트용 가상 오브젝트**임
- 긴 경로를 **하나의 루트 정렬만으로 해결하려고 함**
- 중간 보정 포인트(QR, 마커, anchor)가 아직 없음

## 4. 앞으로의 계획

### 4-1. `AlignTarget` 기반 테스트에서 실제 기준점 기반 정렬로 전환
현재의 `AlignTarget` 구조는 유지하되,  
다음 단계에서는 **QR 마커 또는 실제 공간 기준점**을 이용해  
`NavigationRoot`를 정렬하는 방식으로 전환한다.

### 4-2. 버튼 역할 변경
현재 버튼 역할:
- `AlignTarget` 기준 수동 정렬

앞으로의 버튼 역할:
- **QR 인식 후 정렬 실행**
- 또는 **중간 지점에서 재보정(Recalibration)** 실행

즉, 버튼은 "경로를 내 앞으로 끌어오는 기능"이 아니라  
"현실 기준점에 맞게 다시 정렬하는 기능"이 되어야 한다.

### 4-3. 경로를 실제 길 형태로 확장
현재는 테스트용 오브젝트 중심으로 확인 중이지만,  
다음 단계에서는 다음과 같이 바꾼다.
- `LineRenderer` 또는 여러 개의 segment 오브젝트로 경로 생성
- 바닥을 따라 이어지는 형태로 경로 시각화
- 사용자가 따라 걸을 수 있도록 길 형태 강화

### 4-4. 긴 경로를 여러 구간으로 분리
전체 경로를 하나로 고정하기보다,
- 시작점
- 중간 분기점
- 도착점 근처

이런 식으로 **구간을 나누어 관리**한다.  
각 구간마다 별도 정렬 또는 별도 anchor를 적용하면  
장거리 이동에서 오차 누적을 줄일 수 있다.

### 4-5. 중간 보정 포인트 추가
복도나 환승 경로처럼 길이가 길어질 경우,
- 분기점
- 코너
- 중요한 통과 지점

마다 **QR 또는 마커**를 추가하여  
사용자가 그 지점을 볼 때마다 경로를 다시 맞추는 구조로 발전시킨다.

### 4-6. 회전 정렬 보완
다음 구현 단계에서는 위치 정렬뿐 아니라
- 마커의 forward 방향
- 경로 시작 방향
- Y축 회전 오프셋

을 함께 조정해,  
경로가 실제 진행 방향과 자연스럽게 일치하도록 보완한다.

## 5. 우선순위별 다음 작업

### 1순위
- 현재 버튼 정렬 구조 최종 점검
- `NavigationRoot` / `AlignTarget` / 경로 오브젝트 관계 정리
- 정렬 시 상대 위치 유지 방식 완전 이해

### 2순위
- `LineRenderer` 기반의 실제 길 모양 경로 만들기
- 테스트용 `Cube`, `Capsule` 대신 이어진 길 형태로 시각화

### 3순위
- QR 또는 이미지 마커 인식 연결
- 버튼을 눌렀을 때 `AlignTarget`이 아니라 실제 마커 pose를 기준으로 정렬

### 4순위
- 중간 보정 포인트 도입
- 장거리 이동 시 경로 이탈 문제 완화

### 5순위
- 최종적으로는 "한 번 정렬 후 따라가는 데모"가 아니라
  **현실 공간에 붙어 있는 길 안내 시스템**으로 발전

## 6. 한 줄 정리
현재 시스템은 **버튼을 눌러 가상 경로를 한 번 재배치하는 정렬 데모** 단계이며,  
앞으로는 **실제 QR/마커 기반 정렬 + 구간 분할 + 중간 보정**을 통해  
사용자가 실제로 따라 걸을 수 있는 안정적인 XR 길 안내 시스템으로 발전시켜야 한다.
